    { bits:  5, name: 'rs1' },

let rs1_val = X(rs1);

let output : xlenbits = 0;

foreach (i from 0 to (xlen - 1) by 1) {

            then output ^ (rs1_val << i);
            else output;
}

[[crypto_scalar_introduction]]
=== 引言

本文档描述了 RISC-V 的 _标量_ 密码学扩展。
此处描述的所有指令都使用通用 `X` 寄存器，并遵守 2-读-1-写寄存器访问约束。
这些指令设计为轻量级，适用于 `32` 位和 `64` 位基础架构；从嵌入式 IoT 类核心到不实现向量单元的大型应用类核心。

本文档还描述了熵源的架构接口，可用于生成密码学密钥。
这在 <<crypto_scalar_es>> 中可以找到。

它还包含一种机制，允许核心实现者在 <<crypto_scalar_zkt>> 中提供 _"常数时间执行"_ 保证。

[[crypto_scalar_audience]]
==== 目标受众

密码学是一个专业领域，需要具有不同背景的人员合作才能安全高效地实现。
在可能的情况下，我们编写本规范时力求让所有人都能理解，尽管我们认识到，对于非领域专家来说，动机以及对算法或其他规范和标准的引用可能不熟悉。

本规范预计将被具有不同背景的各种人士阅读和采纳。
我们试图在此处捕捉这些背景，并简要说明我们期望他们了解什么，以及这与规范的关系。
我们希望这有助于人们理解规范的哪些方面与他们特别相关，以及他们可以（安全地！）忽略或交给同事的方面。

密码学家和密码软件开发人员::
我们期望这些人使用本规范中的指令编写代码。
他们应该相当清楚地理解我们包含的指令的动机，并熟悉我们引用的大多数算法和外部标准。
我们期望常数时间执行部分
(<<crypto_scalar_zkt>>)
和熵源部分
(<<crypto_scalar_es>>)
主要在他们的帮助下理解。

计算机架构师::
我们不期望架构师具有密码学背景。
尽管如此，我们仍然期望架构师能够检查我们的指令是否存在实现问题，理解指令将如何在上下文中被使用，并就如何最好地将密码学家想要的功能与 ISA 接口匹配提供建议。

数字设计工程师和微架构师::
这些人将在核心内部实现规范。同样，不假定具备密码学专业知识，但我们期望他们解释规范并预测任何硬件实现问题，例如，在高频设计考虑适用或存在延迟/面积权衡等情况下。
特别是，他们应该了解围绕高效实现 AES 和 SM4 SBox 的文献。

验证工程师::
负责确保扩展在硬件中的正确实现。
不假定具备密码学背景。
我们期望他们从规范中识别有趣的测试用例。了解其在实际世界中的用法将有助于此。
我们不期望验证工程师在这个意义上成为熵源设计或认证的专家，因为这是一个非常专业的领域。
然而，我们确实期望他们识别围绕熵源接口的所有 _架构_ 测试用例。

这些人绝不是唯一关注本规范的人，但他们是我们在撰写本规范时考虑最多的人。

[[crypto_scalar_sail_specifications]]
==== Sail 规范

RISC-V 维护一个
link:https://github.com/riscv/sail-riscv[形式化模型]
的 ISA 规范，
使用 Sail ISA 规范语言实现
cite:[sail]。
注意 _Sail_ 指的是规范语言本身，
并且有一个使用 Sail 编写的 _RISC-V 模型_。
不正确的是指"Sail 模型"。
这是模糊的，因为有许多使用 Sail 实现的不同 ISA 的模型。我们将 RISC-V 的 Sail 实现称为
"RISC-V Sail 模型"。

密码学扩展使用来自实际模型的内联 Sail 代码片段来给出指令功能的规范描述。
每条指令都附有其在 Sail 中的表达式，并包括对支持函数的调用，这些函数太冗长而无法直接包含在规范中。
这些支持代码列在
<<crypto_scalar_appx_sail>>。
建议阅读
link:https://alasdair.github.io/manual.html[Sail 手册]
以便最好地理解代码片段。

请注意，本文档仅包含形式化模型的子集：请参阅形式化模型 GitHub
link:https://github.com/riscv/sail-riscv[仓库]
获取完整模型。

[[crypto_scalar_policies]]
==== 策略

在创建本提案时，我们尝试遵守以下策略：

* 当在以下选择之间有选择时：
  . 支持算法的多样化实现策略
  或
  . 支持单一实现风格，更高性能 / 成本更低；
  密码扩展将选择更受约束但性能更好的选项。
  这符合 RISC-V 规范其他部分的常见模式，
  其中给出了执行特定任务的推荐（但不是必需的）指令序列作为示例，使得硬件和软件实现者都可以仅针对单一用例进行优化。

* 该扩展将设计为良好支持 _现有的_ 标准化密码学构造。
  它不会尝试支持提议的标准或仅存在于学术界的密码学构造。
  与 RISC-V 密码学扩展标准化同时或之后确定的密码学标准将由 RISC-V 密码学标准扩展的未来添加或版本处理。预计 NIST 轻量级密码学竞赛和 NIST 后量子密码学竞赛可能会以这种方式处理，具体取决于时间表。

* 历史上，已经有一些讨论
  cite:[LSYRR:04]
  关于通用计算中新支持的操作如何为密码学算法启用新的基础。
  该标准不会尝试预期新的有用的低级操作，这些操作 _可能_ 作为未来密码学构造的构建块有用。

* 关于侧信道对策：
  在相关的情况下，提议的指令必须旨在消除任何时序侧信道的可能性。
  对于基于功率或电磁（EM）测量的侧信道，该扩展不会旨在支持在 ISA 抽象层之上实现的对策。
  在相关情况下，将给出关于微架构如何以抗功率/EM 侧信道的方式实现指令的建议。

[[crypto_scalar_extensions]]
=== 扩展概述

标量密码学指令集扩展引入的扩展组在此列出。

检测单个密码学扩展使用统一的基于软件的 RISC-V 发现方法。

[NOTE]
====
在撰写本文时，这些发现机制仍在进行中。
====

.扩展原理说明
[NOTE, caption="SH"]
====
专门的加密和解密指令被分成不同的功能组，因为某些用例（例如，TLS 1.3 中的 Galois/Counter 模式）不需要解密功能。

NIST 和 ShangMi 算法套件是分开的，因为它们的有用性在很大程度上取决于设备预期运行的国家。NIST 密码是大多数标准化互联网协议的一部分，而 ShangMi 密码在中国使用是必需的。
====

[[zbkb-sc,Zbkb-sc]]
==== `Zbkb` - 密码学位操作指令

此扩展包含对密码学特别有用的位操作指令，其中大多数也在 `Zbb` 扩展中。
请参阅 <<b-st-ext.adoc#zbkb>>。

[[zbkc-sc,Zbkc-sc]]
==== `Zbkc` - 无进位乘法指令

用于 Galois/Counter 模式的常数时间无进位乘法。
这些与 <<b-st-ext.adoc#zbkb>> 分开，因为它们具有相当大的实现开销，无法在其他指令中摊销。

请参阅 <<b-st-ext.adoc#zbkc>>。

[[zbkx-sc,Zbkx-sc]]
==== `Zbkx` - 交叉置换指令

这些指令对于在常数时间内实现 SBox 很有用，并且可能具有 DPA 保护。
这些与 <<b-st-ext.adoc#zbkb>> 分开，因为它们具有无法在其他指令中摊销的实现开销。

请参阅 <<b-st-ext.adoc#zbkx>>。
