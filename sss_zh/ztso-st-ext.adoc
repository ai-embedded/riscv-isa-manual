[[ztso]]
== “Ztso”全存储排序扩展，版本 1.0

本章定义了 RISC-V 全存储排序 (RVTSO) 内存一致性模型的“Ztso”扩展。RVTSO 是在 <<rvwmo>> 中定义的 RVWMO 的基础上定义的。
[NOTE]
====
_Ztso 扩展旨在方便移植最初为 x86 或 SPARC 架构编写的代码，这两种架构默认都使用 TSO。它还支持固有地提供 RVTSO 行为并希望向软件公开该事实的实现。_
====
RVTSO 对 RVWMO 进行了以下调整：

* 所有加载操作的行为都好像它们具有 acquire-RCpc 注释
* 所有存储操作的行为都好像它们具有 release-RCpc 注释。
* 所有 AMO 的行为都好像它们同时具有 acquire-RCsc 和 release-RCsc 注释。

[NOTE]
====
_这些规则使得除 <<overlapping-ordering, 4-7>> 之外的所有 PPO 规则都变得多余。它们还使得任何没有同时设置 PW 和 SR 的非 I/O 栅栏变得多余。最后，它们还意味着任何内存操作都不会在任一方向上被重新排序到 AMO 之后。_

_在 RVTSO 的上下文中，与 RVWMO 的情况一样，存储排序注释由 PPO 规则 <<overlapping-ordering, 5-7>> 简洁而完整地定义。在这两种内存模型中，都是 <<ax-load>> 允许 hart 将其存储缓冲区中的值转发到后续（按程序顺序）的加载——也就是说，存储可以在对其他 hart 可见之前在本地转发。_
====

此外，如果实现了 Ztso 扩展，则 V 扩展和 Zve 系列扩展中的向量内存指令在指令级别遵循 RVTSO。
Ztso 扩展不加强指令内元素访问的排序。

尽管 Ztso 没有向 ISA 添加任何新指令，但假定 RVTSO 编写的代码在不支持 Ztso 的实现上将无法正确运行。编译为仅在 Ztso 下运行的二进制文件应通过二进制文件中的标志来指示，以便不支持 Ztso 的平台可以简单地拒绝运行它们。

=== RVTSO 与 RVWMO 的对比

**内存排序强度**：
- **RVWMO**：弱一致性模型，允许更多的重新排序
- **RVTSO**：更强的一致性模型，限制重新排序

**性能影响**：
- **RVWMO**：更高的性能潜力，但需要更仔细的同步
- **RVTSO**：可能较低的性能，但更易于程序推理

**编程模型**：
- **RVWMO**：需要显式的内存栅栏来确保排序
- **RVTSO**：隐式提供更强的排序保证

=== 迁移考虑

**从 x86/SPARC 迁移的好处**：
1. **代码兼容性**：减少需要的同步修改
2. **调试简化**：一致性错误更容易重现和诊断
3. **验证工具**：现有的 x86/SPARC 验证工具更容易适配

**性能权衡**：
- 可能牺牲一些性能换取编程简单性
- 减少了编译器和硬件的优化机会
- 但简化了多线程程序的正确性保证

=== 实现指南

**硬件实现策略**：
1. **保守实现**：所有内存操作都按程序顺序执行
2. **优化实现**：在保证 TSO 语义的前提下进行有限的重新排序
3. **混合实现**：根据工作负载动态调整内存一致性级别

**软件工具链支持**：
- 编译器需要识别 Ztso 目标
- 调试器应理解 RVTSO 语义
- 性能分析工具需要考虑内存排序开销

=== 向量扩展交互

**指令级别的 RVTSO**：
- 向量加载/存储指令遵循 RVTSO 规则
- 与标量内存操作的排序保持一致
- 确保向量和标量代码的混合正确性

**元素级别的自由度**：
- 向量指令内部的元素访问顺序不受限制
- 允许向量单元进行内部优化
- 平衡一致性要求和向量性能

=== 二进制兼容性

**标志机制**：
```
ELF header 中的标志位：
- EF_RISCV_TSO: 表示需要 RVTSO 支持
- 运行时检查和拒绝机制
```

**平台检测**：
```c
// 检测平台是否支持 Ztso
bool check_ztso_support() {
    // 通过 EEI 或系统调用查询
    return platform_supports_ztso();
}
```

**动态适配**：
- 某些代码可能能够在两种模型下运行
- 运行时性能调整
- 条件编译支持

=== 调试和验证

**一致性测试**：
- 标准 TSO 测试套件的适配
- 与 x86 行为的对比验证
- 压力测试和竞态条件检测

**性能基准测试**：
- RVTSO vs RVWMO 性能对比
- 内存密集型应用的评估
- 多线程扩展性分析

**开发工具支持**：
- 内存模型可视化工具
- 竞态条件检测器
- 性能分析器的 TSO 感知

Ztso 扩展为需要更强内存一致性保证的应用提供了重要选择，特别适合从 x86 或 SPARC 架构迁移的代码，以及需要简化并发编程模型的应用场景。
