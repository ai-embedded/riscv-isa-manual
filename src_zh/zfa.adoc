[[zfa]]
== “Zfa”——附加浮点指令扩展，版本 1.0

本章描述 Zfa 标准扩展，该扩展增加了用于立即数加载、IEEE 754-2019 最小和最大值运算、舍入到整数运算以及静默浮点比较的指令。对于 RV32D，Zfa 扩展还增加了用于在整数寄存器之间传输双精度浮点值的指令，对于 RV64Q，它增加了用于四精度浮点值的类似指令。Zfa 扩展依赖于 F 扩展。

=== 立即数加载指令

如果实现了 D 扩展，FLI.D 执行类似的操作，但将双精度值加载到浮点寄存器 _rd_ 中。请注意，条目 1（对应于最小正规数值）对于双精度的数值与单精度的数值不同。FLI.D 的编码方式与 FLI.S 类似，但 _fmt_=D。

如果实现了 Q 扩展，FLI.Q 执行类似的操作，但将四精度值加载到浮点寄存器 _rd_ 中。请注意，条目 1（对应于最小正规数值）对于四精度的数值与单精度的数值不同。FLI.Q 的编码方式与 FLI.S 类似，但 _fmt_=Q。

如果实现了 Zfh 或 Zvfh 扩展，FLI.H 执行类似的操作，但将半精度浮点值加载到寄存器 _rd_ 中。请注意，条目 1（对应于最小正规数值）对于半精度的数值与单精度的数值不同。此外，由于 latexmath:[$2^{16}$] 在半精度浮点中无法表示，因此表中的条目 29 会加载正无穷大，即它与条目 30 是多余的。FLI.H 的编码方式与 FLI.S 类似，但 _fmt_=H。
[NOTE]
====
此外，由于 latexmath:[$2^{-16}$] 和 latexmath:[$2^{-15}$] 在半精度中是次正规数，因此对于 FLI.H，条目 1 的数值大于条目 2 和 3。
====
FLI._fmt_ 指令从不设置任何浮点异常标志。

=== 最小和最大指令

FMINM.S 和 FMAXM.S 指令的定义与 FMIN.S 和 FMAX.S 指令类似，只是如果任一输入为 NaN，则结果为规范 NaN。

如果实现了 D 扩展，则类似地定义 FMINM.D 和 FMAXM.D 指令以对双精度数进行操作。

如果实现了 Zfh 扩展，则类似地定义 FMINM.H 和 FMAXM.H 指令以对半精度数进行操作。

如果实现了 Q 扩展，则类似地定义 FMINM.Q 和 FMAXM.Q 指令以对四精度数进行操作。

这些指令的编码方式与其 FMIN 和 FMAX 对应指令类似，但指令位 13 设置为 1。
[NOTE]
====
这些指令实现了 IEEE 754-2019 的最小和最大值运算。
====
=== 舍入到整数指令

FROUND.S 指令根据指令的 _rm_ 字段中指定的舍入模式，将浮点寄存器 _rs1_ 中的单精度浮点数舍入为整数。然后，它将该整数（表示为单精度浮点数）写入浮点寄存器 _rd_。零和无穷大输入将未经修改地复制到 _rd_。信令 NaN 输入会导致设置无效操作异常标志；不会设置其他异常标志。FROUND.S 的编码方式与 FCVT.S.D 类似，但 _rs2_=4。

FROUNDNX.S 指令的定义类似，但如果输入与舍入结果不同且不是 NaN，它还会设置不精确异常标志。FROUNDNX.S 的编码方式与 FCVT.S.D 类似，但 _rs2_=5。

如果实现了 D 扩展，则类似地定义 FROUND.D 和 FROUNDNX.D 指令以对双精度数进行操作。它们的编码方式与 FCVT.D.S 类似，但 _rs2_ 分别为 4 和 5。

如果实现了 Zfh 扩展，则类似地定义 FROUND.H 和 FROUNDNX.H 指令以对半精度数进行操作。它们的编码方式与 FCVT.H.S 类似，但 _rs2_ 分别为 4 和 5。

如果实现了 Q 扩展，则类似地定义 FROUND.Q 和 FROUNDNX.Q 指令以对四精度数进行操作。它们的编码方式与 FCVT.Q.S 类似，但 _rs2_ 分别为 4 和 5。
[NOTE]
====
FROUNDNX._fmt_ 指令实现了 IEEE 754-2019 的 roundToIntegralExact 运算，而 FROUND._fmt_ 指令实现了 roundToIntegral 族中的其他运算。
====
=== 模块化转换为整数指令

FCVTMOD.W.D 指令的定义与 FCVT.W.D 指令类似，但有以下区别。FCVTMOD.W.D 始终向零舍入。从舍入的、无界的二进制补码结果中取位 31:0，然后符号扩展到 XLEN 位并写入整数寄存器 _rd_。latexmath:[$\pm\infty$] 和 NaN 将转换为零。

浮点异常标志的引发方式与具有相同输入操作数的 FCVT.W.D 相同。

仅当实现了 D 扩展时才提供此指令。它的编码方式与 FCVT.W.D 类似，但 rs2 字段设置为 8，_rm_ 字段设置为 1 (RTZ)。其他 _rm_ 值为_保留_。
[NOTE]
====
汇编语法要求明确指定 RTZ 舍入模式，即 `fcvtmod.w.d rd, rs1, rtz`。

添加 FCVTMOD.W.D 指令主要是为了加速 JavaScript 数字的处理。数字是双精度值，但某些运算符会隐式地将它们截断为有符号整数模 latexmath:[$2^{32}$]。
====
=== 移动指令

仅对于 RV32，如果实现了 D 扩展，则 FMVH.X.D 指令将浮点寄存器 _rs1_ 的位 63:32 移动到整数寄存器 _rd_ 中。它在 OP-FP 主操作码中编码，_funct3_=0，_rs2_=1，_funct7_=1110001。
[NOTE]
====
FMVH.X.D 与现有的 FMV.X.W 指令结合使用，可将双精度浮点数移动到一对 x 寄存器中。
====
仅对于 RV32，如果实现了 D 扩展，则 FMVP.D.X 指令将双精度数从一对整数寄存器移动到浮点寄存器中。整数寄存器 _rs1_ 和 _rs2_ 分别提供位 31:0 和 63:32；结果写入浮点寄存器 _rd_。FMVP.D.X 在 OP-FP 主操作码中编码，_funct3_=0，_funct7_=1011001。

仅对于 RV64，如果实现了 Q 扩展，则 FMVH.X.Q 指令将浮点寄存器 _rs1_ 的位 127:64 移动到整数寄存器 _rd_ 中。它在 OP-FP 主操作码中编码，_funct3_=0，_rs2_=1，_funct7_=1110011。
[NOTE]
====
FMVH.X.Q 与现有的 FMV.X.D 指令结合使用，可将四精度浮点数移动到一对 x 寄存器中。
====
仅对于 RV64，如果实现了 Q 扩展，则 FMVP.Q.X 指令将双精度数从一对整数寄存器移动到浮点寄存器中。整数寄存器 _rs1_ 和 _rs2_ 分别提供位 63:0 和 127:64；结果写入浮点寄存器 _rd_。FMVP.Q.X 在 OP-FP 主操作码中编码，_funct3_=0，_funct7_=1011011。

=== 比较指令

FLEQ.S 和 FLTQ.S 指令的定义与 FLE.S 和 FLT.S 指令类似，只是静默 NaN 输入不会导致设置无效操作异常标志。

如果实现了 D 扩展，则类似地定义 FLEQ.D 和 FLTQ.D 指令以对双精度数进行操作。

如果实现了 Zfh 扩展，则类似地定义 FLEQ.H 和 FLTQ.H 指令以对半精度数进行操作。

如果实现了 Q 扩展，则类似地定义 FLEQ.Q 和 FLTQ.Q 指令以对四精度数进行操作。

这些指令的编码方式与其 FLE 和 FLT 对应指令类似，但指令位 14 设置为 1。
[NOTE]
====
我们不希望将类似的比较指令添加到向量 ISA 中，因为可以使用掩码相当有效地模拟它们。
====

=== 性能优化指导

==== 立即数加载优化

FLI._fmt_ 指令的高效使用：

* **常量池替代**：使用 FLI 指令代替从内存加载常见浮点常量
* **代码大小优化**：减少需要存储在常量池中的值
* **初始化优化**：快速初始化浮点寄存器为常用值

==== 舍入操作优化

FROUND 和 FROUNDNX 指令的应用场景：

* **数值处理算法**：实现高效的舍入操作
* **信号处理**：音频和图像处理中的量化操作
* **金融计算**：精确的货币舍入操作

=== 应用场景分析

==== JavaScript 引擎优化

FCVTMOD.W.D 指令专为 JavaScript 设计：

* **位运算优化**：加速 JavaScript 的按位操作
* **类型转换**：高效的 Number 到 32 位整数转换
* **性能提升**：避免复杂的软件模拟序列

==== 科学计算应用

* **IEEE 754-2019 兼容性**：支持最新标准的最小/最大操作
* **精确比较**：FLEQ/FLTQ 指令避免异常处理开销
* **数值稳定性**：精确的舍入控制提高算法稳定性

=== 编程最佳实践

==== 指令选择策略

* **NaN 处理**：根据需要选择 FMIN/FMAX 或 FMINM/FMAXM
* **异常管理**：使用 FLEQ/FLTQ 避免不必要的异常
* **精度控制**：合理使用 FROUND 系列指令

==== 代码优化技巧

* **常量优化**：识别可用 FLI 指令加载的常量
* **移动指令**：在 RV32D 和 RV64Q 中高效传输宽浮点值
* **舍入模式**：选择合适的舍入模式以满足算法需求

=== 调试和验证

==== 正确性验证

* **IEEE 754 合规性**：验证操作符合 IEEE 754-2019 标准
* **边界条件测试**：测试 NaN、无穷大和零的处理
* **舍入精度**：验证不同舍入模式的正确性

==== 性能分析

* **指令吞吐量**：测量 Zfa 指令的执行性能
* **代码大小影响**：评估使用 FLI 对代码大小的改善
* **异常处理开销**：比较静默比较与传统比较的性能差异
