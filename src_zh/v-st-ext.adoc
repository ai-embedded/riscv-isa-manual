[[vector]]
== “V”向量操作标准扩展，版本 1.0

[NOTE]
====
_基本向量扩展旨在在 32 位指令编码空间内提供对数据并行执行的通用支持，后续向量扩展将为特定领域提供更丰富的功能。_
====

=== 引言

本规范包括当前冻结的向量指令的完整集合。在开发过程中考虑过但未出现在本文档中的其他指令不包括在审查和批准过程中，并且可能会完全修订或放弃。<<sec-vector-extensions>> 列出了标准向量扩展以及每个扩展支持的指令和元素宽度。

=== 实现定义的常量参数

每个支持向量扩展的 hart 定义两个参数：

. 任何操作可以产生或消耗的向量元素的最大位大小，_ELEN_ ≥ 8，必须是 2 的幂。
. 单个向量寄存器中的位数，_VLEN_ ≥ ELEN，必须是 2 的幂，并且不得大于 2^16^。

标准向量扩展（<<sec-vector-extensions>>）和架构配置文件可能会对 _ELEN_ 和 _VLEN_ 设置进一步的约束。

NOTE: 未来的扩展可能允许 ELEN > VLEN，通过使用多个向量寄存器中的位来保存一个元素，但当前提案不包括此选项。

NOTE: VLEN 的上限允许软件知道索引将适合 16 位（LMUL=8 和 SEW=8 且 VLEN=65,536 时，最大 VLMAX 为 65,536）。任何超出每个向量寄存器 64KiB 的未来扩展都需要新的配置指令，以便使用旧配置指令的软件不会看到更大的向量长度。

向量扩展支持编写二进制代码，该代码在某些约束下可以在具有不同 VLEN 参数的 hart 上可移植地执行，前提是 hart 支持所需的元素类型和指令。

NOTE: 可以编写代码来暴露实现参数的差异。

NOTE: 通常，具有活动向量状态的线程上下文在执行期间不能在 VLEN 或 ELEN 参数有任何差异的 hart 之间迁移。

=== 向量扩展程序员模型

向量扩展向基本标量 RISC-V ISA 添加了 32 个向量寄存器和七个非特权 CSR（`vstart`、`vxsat`、`vxrm`、`vcsr`、`vtype`、`vl`、`vlenb`）。

.新向量 CSR
[cols="2,2,2,10"]
[%autowidth,float="center",align="center",options="header"]
|===
| 地址 | 特权 | 名称   | 描述

| 0x008 | URW | vstart | 向量起始元素索引
| 0x009 | URW | vxsat  | 定点饱和标志
| 0x00A | URW | vxrm   | 定点舍入模式
| 0x00F | URW | vcsr   | 向量控制和状态寄存器
| 0xC20 | URO | vl     | 向量长度
| 0xC21 | URO | vtype  | 向量数据类型寄存器
| 0xC22 | URO | vlenb  | VLEN/8（向量寄存器字节长度）
|===

NOTE: CSR 编号 `0x00B`-`0x00E` 暂时保留用于未来的向量 CSR，其中一些可能会镜像到 `vcsr` 中。

==== 向量寄存器

向量扩展向基本标量 RISC-V ISA 添加了 32 个架构向量寄存器 `v0`-`v31`。

每个向量寄存器都有固定的 VLEN 位状态。

==== `mstatus` 中的向量上下文状态

向量上下文状态字段 `VS` 添加到 `mstatus[10:9]` 中，并镜像到 `sstatus[10:9]` 中。它的定义类似于浮点上下文状态字段 `FS`。

当 `mstatus.VS` 设置为 Off 时，尝试执行任何向量指令或访问向量 CSR 会引发非法指令异常。

当 `mstatus.VS` 设置为 Initial 或 Clean 时，执行任何更改向量状态的指令（包括向量 CSR）都会将 `mstatus.VS` 更改为 Dirty。
实现也可以随时将 `mstatus.VS` 从 Initial 或 Clean 更改为 Dirty，即使向量状态没有改变。

NOTE: `mstatus.VS` 的准确设置是一种优化。软件通常会使用 VS 来减少上下文切换开销。

如果 `mstatus.VS` 为 Dirty，则 `mstatus.SD` 为 1；否则，`mstatus.SD` 根据现有规范设置。

实现可以具有可写的 `misa.V` 字段。类似于处理浮点单元的方式，即使 `misa.V` 清除，`mstatus.VS` 字段也可能存在。

NOTE: 允许 `mstatus.VS` 在 `misa.V` 清除时存在，可以启用向量仿真，并简化在具有可写 `misa.V` 的系统中处理 `mstatus.VS`。

==== `vsstatus` 中的向量上下文状态

当 hypervisor 扩展存在时，向量上下文状态字段 `VS` 添加到 `vsstatus[10:9]` 中。
它的定义类似于浮点上下文状态字段 `FS`。

当 V=1 时，`vsstatus.VS` 和 `mstatus.VS` 都生效：当任一字段设置为 Off 时，尝试执行任何向量指令或访问向量 CSR 会引发非法指令异常。

当 V=1 且 `vsstatus.VS` 和 `mstatus.VS` 均未设置为 Off 时，执行任何更改向量状态的指令（包括向量 CSR）都会将 `mstatus.VS` 和 `vsstatus.VS` 都更改为 Dirty。
实现也可以随时将 `mstatus.VS` 或 `vsstatus.VS` 从 Initial 或 Clean 更改为 Dirty，即使向量状态没有改变。

如果 `vsstatus.VS` 为 Dirty，则 `vsstatus.SD` 为 1；否则，`vsstatus.SD` 根据现有规范设置。

如果 `mstatus.VS` 为 Dirty，则 `mstatus.SD` 为 1；否则，`mstatus.SD` 根据现有规范设置。

对于具有可写 `misa.V` 字段的实现，即使 `misa.V` 清除，`vsstatus.VS` 字段也可能存在。

==== 向量类型 (`vtype`) 寄存器

只读 XLEN 宽度的 _向量_ _类型_ CSR `vtype` 提供用于解释向量寄存器文件内容的默认类型，并且只能通过 `vset{i}vl{i}` 指令更新。向量类型决定了每个向量寄存器中元素的组织方式，以及多个向量寄存器如何分组。`vtype` 寄存器还指示如何处理被屏蔽的元素和向量结果中超出当前向量长度的元素。

NOTE: 仅允许通过 `vset{i}vl{i}` 指令更新，简化了 `vtype` 寄存器状态的维护。

`vtype` 寄存器有五个字段：`vill`、`vma`、`vta`、`vsew[2:0]` 和 `vlmul[2:0]`。`vtype[XLEN-2:8]` 位应写入零，此字段中的非零值是保留的。

include::images/wavedrom/vtype-format.edn[]

NOTE: 支持 ELEN=32 的小型实现只需要 `vtype` 中七位状态：`ma` 和 `ta` 的两位，`vsew[1:0]` 的两位和 `vlmul[2:0]` 的三位。`vill` 表示的非法值可以在内部使用 `vsew[1:0]` 中的非法 64 位组合进行编码，而无需额外的存储位来保存 `vill`。

NOTE: 未来的标准和自定义向量扩展可能会扩展这些字段以支持更多样化的数据类型。

NOTE: `vtype` CSR 的主要动机是允许向量指令集适应 32 位指令编码空间。单独的 `vset{i}vl{i}` 指令可用于在向量指令执行之前设置 `vl` 和/或 `vtype` 字段，并且实现可以选择将这两个指令融合为单个内部向量微操作。在许多情况下，`vl` 和 `vtype` 值可以在多个指令之间重用，从而减少 `vset{i}vl{i}` 指令的静态和动态指令开销。预计未来的扩展 64 位指令编码将允许这些字段在指令编码中静态指定。

===== 向量选择元素宽度 (`vsew[2:0]`)

`vsew` 中的值设置动态 _选择_ _元素_ _宽度_ (SEW)。默认情况下，向量寄存器被视为分为 VLEN/SEW 个元素。

.vsew[2:0]（选择元素宽度）编码
[cols="1,1,1,1"]
[%autowidth,float="center",align="center",options="header"]
|===
3+| vsew[2:0] | SEW

| 0 | 0 | 0 |    8
| 0 | 0 | 1 |   16
| 0 | 1 | 0 |   32
| 0 | 1 | 1 |   64
| 1 | X | X |   保留
|===

NOTE: 尽管预计较大的 `vsew[2:0]` 编码（`100`-`111`）将用于编码较大的 SEW，但这些编码目前正式 _保留_。

.示例 VLEN = 128 位
[cols=">,>"]
[%autowidth,float="center",align="center",options="header"]
|===
| SEW | 每个向量寄存器的元素数

| 64 |  2
| 32 |  4
| 16 |  8
|  8 | 16
|===

支持的元素宽度可能随 LMUL 而变化。

NOTE: 当前的标准向量扩展不随 LMUL 改变支持的元素宽度。一些未来的扩展可能仅在多个向量寄存器中的位使用 LMUL 组合时才支持较大的 SEW。在这种情况下，依赖大 SEW 的软件应尝试使用最大的 LMUL，从而使用最少的向量寄存器组，以增加代码运行的实现数量。在设置 `vtype` 后应检查 `vtype` 中的 `vill` 位，以查看配置是否受支持，如果不支持，则应提供备用代码路径。或者，配置文件可以强制规定每个 LMUL 设置的最小 SEW。

===== 向量寄存器分组 (`vlmul[2:0]`)

多个向量寄存器可以分组在一起，以便单个向量指令可以操作多个向量寄存器。术语 _向量_ _寄存器_ _组_ 在此用于指代一个或多个向量寄存器，作为向量指令的单个操作数。向量寄存器组可用于为更长的应用程序向量提供更高的执行效率，但包含它们的主要原因是允许以与单宽度元素相同的向量长度操作双宽度或更大元素。向量长度乘数 _LMUL_，当大于 1 时，表示组合形成向量寄存器组的默认向量寄存器数量。实现必须支持 LMUL 整数值 1、2、4 和 8。


NOTE: 向量架构包括采用多个源和目标向量操作数且元素宽度不同但元素数量相同的指令。每个向量操作数的有效 LMUL (EMUL) 由保存元素所需的寄存器数量决定。例如，对于加宽加法操作，例如添加 32 位值以产生 64 位结果，双宽度结果需要两倍于单宽度输入的 LMUL。

LMUL 也可以是分数，减少单个向量寄存器中使用的位数。分数 LMUL 用于在操作混合宽度值时增加有效可用向量寄存器组的数量。

NOTE: 仅使用整数 LMUL 值，操作一系列大小的循环必须为最窄的数据类型分配至少一个完整的向量寄存器 (LMUL=1)，然后消耗多个向量寄存器 (LMUL>1) 以形成每个更宽向量操作数的向量寄存器组。这会限制可用向量寄存器组的数量。使用分数 LMUL，最宽的值只需要占用单个向量寄存器，而较窄的值可以占用单个向量寄存器的一部分，从而允许所有 32 个架构向量寄存器名称用于向量循环中的不同值，即使在处理混合宽度值时也是如此。分数 LMUL 意味着向量寄存器的一部分未被使用，但在某些情况下，拥有更多更短的寄存器驻留向量相对于更少更长的寄存器驻留向量提高了效率。_

实现必须提供分数 LMUL 设置，允许最窄支持类型占用向量寄存器的一部分，该部分对应于最窄支持类型的宽度与最大支持类型的宽度之比。通常，要求是支持 LMUL ≥ SEW~MIN~/ELEN，其中 SEW~MIN~ 是最窄支持的 SEW 值，ELEN 是最宽支持的 SEW 值。在标准扩展中，SEW~MIN~=8。对于 ELEN=32 的标准向量扩展，必须支持 1/2 和 1/4 的分数 LMUL。对于 ELEN=64 的标准向量扩展，必须支持 1/2、1/4 和 1/8 的分数 LMUL。

NOTE: 当 LMUL < SEW~MIN~/ELEN 时，不能保证实现将在分数向量寄存器中拥有足够的位来存储至少一个元素，因为 VLEN=ELEN 是一个有效的实现选择。例如，当 VLEN=ELEN=32 且 SEW~MIN~=8 时，LMUL 为 1/8 将只在向量寄存器中提供四位存储。

对于给定的支持分数 LMUL 设置，实现必须支持 SEW~MIN~ 和 LMUL * ELEN 之间（包括两者）的 SEW 设置。

LMUL < SEW~MIN~/ELEN 的 `vtype` 编码是 __保留的__，但如果实现不支持这些配置，则可以设置 `vill`。

NOTE: 在这种情况下要求所有实现都设置 `vill` 将禁止将来在扩展中使用此情况，因此为了允许将来定义 LMUL<SEW~MIN~/ELEN 行为，我们认为使用此情况是 __保留的__。

NOTE: 建议汇编器在 `vsetvli` 指令尝试写入 LMUL < SEW~MIN~/ELEN 时发出警告（而不是错误）。

LMUL 由 `vtype` 中的有符号 `vlmul` 字段设置（即 LMUL = 2^`vlmul[2:0]`^）。

派生值 VLMAX = LMUL*VLEN/SEW 表示在给定当前 SEW 和 LMUL 设置的情况下，单个向量指令可以操作的最大元素数量，如下表所示。

[cols="1,1,1,2,2,5,5"]
[%autowidth,float="center",align="center",options="header"]
|===
  3+| vlmul[2:0] | LMUL | #组 | VLMAX      | 与寄存器 __n__ 分组的寄存器

| 1 | 0 | 0 |   -  |     -   |     -      | 保留
| 1 | 0 | 1 |   1/8|     32  | VLEN/SEW/8 | `v` __n__（组中单个寄存器）
| 1 | 1 | 0 |   1/4|     32  | VLEN/SEW/4 | `v` __n__（组中单个寄存器）
| 1 | 1 | 1 |   1/2|     32  | VLEN/SEW/2 | `v` __n__（组中单个寄存器）
| 0 | 0 | 0 |   1  |     32  |   VLEN/SEW | `v` __n__（组中单个寄存器）
| 0 | 0 | 1 |   2  |     16  | 2*VLEN/SEW | `v` __n__, `v` __n__+1
| 0 | 1 | 0 |   4  |      8  | 4*VLEN/SEW | `v` __n__, ..., `v` __n__+3
| 0 | 1 | 1 |   8  |      4  | 8*VLEN/SEW | `v` __n__, ..., `v` __n__+7
|===

当 LMUL=2 时，向量寄存器组包含向量寄存器 `v` __n__ 和向量寄存器 `v` __n__+1，提供两倍的向量长度（以位为单位）。指定 LMUL=2 向量寄存器组且向量寄存器为奇数编号的指令是保留的。

当 LMUL=4 时，向量寄存器组包含四个向量寄存器，并且指定 LMUL=4 向量寄存器组且向量寄存器编号不是四的倍数的指令是保留的。

当 LMUL=8 时，向量寄存器组包含八个向量寄存器，并且指定 LMUL=8 向量寄存器组且寄存器编号不是八的倍数的指令是保留的。

无论 SEW 和 LMUL 如何，掩码寄存器始终包含在单个向量寄存器中。

[[sec-agnostic]]
===== 向量尾部无关和向量掩码无关 `vta` 和 `vma`

这两个位分别修改了向量指令执行期间目标尾部元素和目标非活动被屏蔽元素的行为。尾部和非活动集包含在向量操作期间未接收新结果的元素位置，如 <<sec-inactive-defs>> 中定义。

所有系统都必须支持所有四个选项：

[cols="1,1,3,3"]
[%autowidth,float="center",align="center",options="header"]
|===
| `vta` | `vma` | 尾部元素 | 非活动元素

|   0   |   0   | 不受干扰   | 不受干扰
|   0   |   1   | 不受干扰   | 无关
|   1   |   0   | 无关      | 不受干扰
|   1   |   1   | 无关      | 无关
|===

无论 `vta` 的设置如何，掩码目标尾部元素始终被视为尾部无关。

当一个集合被标记为不受干扰时，向量寄存器组中相应的目标元素集合保留它们先前持有的值。

当一个集合被标记为无关时，任何向量目标操作数中相应的目标元素集合可以保留它们先前持有的值，或者被 1 覆盖。在单个向量指令中，每个目标元素可以保持不受干扰或被 1 覆盖，以任何组合，并且当指令以相同输入执行时，不受干扰或被 1 覆盖的模式不需要是确定性的。

NOTE: 添加无关策略是为了适应具有向量寄存器重命名的机器。使用不受干扰策略，所有元素都必须从旧的物理目标向量寄存器读取，才能复制到新的物理目标向量寄存器。当这些非活动或尾部值不需要用于后续计算时，这会导致效率低下。

NOTE: 选择所有 1 而不是所有 0 作为覆盖值是为了阻止软件开发人员依赖写入的值。

NOTE: 简单的顺序实现可以忽略设置，并简单地使用不受干扰策略执行所有向量指令。`vta` 和 `vma` 状态位仍必须在 `vtype` 中提供，以实现兼容性并支持线程迁移。

NOTE: 乱序实现可以选择使用尾部无关 + 掩码不受干扰来实现尾部无关 + 掩码无关，以降低实现复杂性。

NOTE: 无关结果策略的定义是宽松的，以适应在小型顺序核心（可能使无关区域不受干扰）和具有寄存器重命名的大型乱序核心（可能用 1 覆盖无关元素）之间迁移应用程序线程。由于可能需要在中间重新启动，我们允许在单个向量指令中任意混合无关策略。这种允许混合策略也使得实现可以为向量寄存器的不同粒度更改策略，例如，在活动操作的粒度内使用不受干扰，但对于尾部中的粒度重命名为所有 1。

此外，除了掩码加载指令外，掩码结果尾部中的任何元素也可以写入掩码生成操作在 `vl`=VLMAX 时计算的值。
此外，对于掩码逻辑指令和 `vmsbf.m`、`vmsif.m`、`vmsof.m` 掩码操作指令，结果尾部中的任何元素都可以写入掩码生成操作在 `vl`=VLEN、SEW=8 和 LMUL=8 时计算的值（即，掩码寄存器的所有位都可以被覆盖）。

NOTE: 掩码尾部始终被视为无关，以降低管理掩码数据的复杂性，掩码数据可以按位粒度写入。似乎很少有软件需要支持掩码寄存器值的尾部不受干扰。允许掩码生成指令写回指令结果避免了对尾部进行掩码的逻辑需求，但掩码加载不能将内存值写入目标掩码尾部，因为这会意味着访问超出软件意图的内存。

汇编语法向 `vsetvli` 指令添加了两个强制标志：

----
 ta   # 尾部无关
 tu   # 尾部不受干扰
 ma   # 掩码无关
 mu   # 掩码不受干扰

 vsetvli t0, a0, e32, m4, ta, ma   # 尾部无关，掩码无关
 vsetvli t0, a0, e32, m4, tu, ma   # 尾部不受干扰，掩码无关
 vsetvli t0, a0, e32, m4, ta, mu   # 尾部无关，掩码不受干扰
 vsetvli t0, a0, e32, m4, tu, mu   # 尾部不受干扰，掩码不受干扰
----

NOTE: 在 v0.9 之前，当 `vsetvli` 上未指定这些标志时，它们默认为掩码不受干扰/尾部不受干扰。然而，不带这些标志的 `vsetvli` 的使用已被弃用，现在指定标志设置是强制性的。默认值可能应该是尾部无关/掩码无关，因此软件必须指定何时关心不参与的元素，但考虑到引入这些标志之前指令的历史含义，决定将来在汇编代码中始终要求它们。

===== 向量类型非法 (`vill`)

`vill` 位用于编码先前的 `vset{i}vl{i}` 指令尝试向 `vtype` 写入不支持的值。

NOTE: `vill` 位保存在 CSR 的 XLEN-1 位中，以支持通过符号位上的分支检查非法值。

如果 `vill` 位设置，则任何尝试执行依赖于 `vtype` 的向量指令都将引发非法指令异常。

NOTE: `vset{i}vl{i}` 和全寄存器加载和存储不依赖于 `vtype`。

当 `vill` 位设置时，`vtype` 中的其他 XLEN-1 位应为零。

==== 向量长度 (`vl`) 寄存器

_XLEN_ 位宽的只读 `vl` CSR 只能通过 `vset{i}vl{i}` 指令以及 _仅故障优先_ 向量加载指令变体更新。

`vl` 寄存器保存一个无符号整数，指定要用向量指令更新结果的元素数量，如 <<sec-inactive-defs>> 中进一步详细说明。

NOTE: `vl` 中实现的位数取决于实现支持的最小类型的最大向量长度。VLEN=32 且支持 SEW=8 的最小向量实现将需要 `vl` 中至少六位来保存值 0-32（VLEN=32，LMUL=8 且 SEW=8，产生 VLMAX=32）。

==== 向量字节长度 (`vlenb`) 寄存器

_XLEN_ 位宽的只读 CSR `vlenb` 保存值 VLEN/8，即向量寄存器字节长度。

NOTE: `vlenb` 中的值是任何实现中的设计时常量。

NOTE: 没有此 CSR，需要多条指令来计算字节中的 VLEN，并且代码必须干扰当前的 `vl` 和 `vtype` 设置，这需要保存和恢复它们。

==== 向量起始索引 (`vstart`) 寄存器

_XLEN_ 位宽的读写 `vstart` CSR 指定向量指令要执行的第一个元素的索引，如 <<sec-inactive-defs>> 中所述。

通常，`vstart` 仅在向量指令上发生陷阱时由硬件写入，`vstart` 值表示发生陷阱的元素（同步异常或异步中断），以及在处理可恢复陷阱后应恢复执行的元素。

所有向量指令都定义为从 `vstart` CSR 中给定的元素编号开始执行，保留目标向量中较早的元素不受干扰，并在执行结束时将 `vstart` CSR 重置为零。

NOTE: 所有向量指令，包括 `vset{i}vl{i}`，都将 `vstart` CSR 重置为零。

`vstart` 不受引发非法指令异常的向量指令修改。

`vstart` CSR 定义为只具有足够的写入位来保存最大元素索引（比最大 VLMAX 小一）。

NOTE: 最大向量长度是通过最大 LMUL 设置 (8) 和最小 SEW 设置 (8) 获得的，因此 VLMAX_max = 8*VLEN/8 = VLEN。例如，对于 VLEN=256，`vstart` 将有 8 位来表示从 0 到 255 的索引。

使用大于当前 `vtype` 设置的最大元素索引的 `vstart` 值是保留的。

NOTE: 建议实现如果 `vstart` 超出范围则捕获。不要求捕获，因为 `vstart` 上位可能的未来用途是存储不精确的陷阱信息。

`vstart` CSR 可由非特权代码写入，但非零 `vstart` 值可能导致向量指令在某些实现上运行速度显著变慢，因此应用程序程序员不应使用 `vstart`。少数向量指令不能以非零 `vstart` 值执行，并且将引发非法指令异常，如下所述。

NOTE: 使 `vstart` 对非特权代码可见支持用户级线程库。

实现允许在尝试执行向量指令时，如果 `vstart` 的值是实现永远无法在相同 `vtype` 设置下执行相同指令时产生的值，则引发非法指令异常。

NOTE: 例如，某些实现永远不会在向量算术指令执行期间接受中断，而是等到指令完成才接受中断。此类实现允许在尝试执行向量算术指令时，如果 `vstart` 非零，则引发非法指令异常。

NOTE: 在两个具有不同微架构的 hart 之间迁移软件线程时，`vstart` 值可能不受新 hart 微架构支持。接收 hart 上的运行时可能必须模拟指令执行，直到下一个支持的 `vstart` 元素位置。或者，迁移事件可以限制为仅在相互支持的 `vstart` 位置发生。

==== 向量定点舍入模式 (`vxrm`) 寄存器

向量定点舍入模式寄存器在最低有效位中保存一个两位读写舍入模式字段（`vxrm[1:0]`）。高位 `vxrm[XLEN-1:2]` 应写入零。

向量定点舍入模式被赋予单独的 CSR 地址以允许独立访问，但也作为 `vcsr` 中的一个字段反映。

NOTE: 可以设置新的舍入模式，同时使用单个 `csrwi` 指令保存原始舍入模式。

定点舍入算法指定如下。
假设舍入前结果为 `v`，并且该结果的 `d` 位将被舍入掉。
则舍入结果为 `(v >> d) + r`，其中 `r` 取决于下表中指定的舍入模式。

.vxrm 编码
//[cols="1,1,4,10,5"]
[%autowidth,float="center",align="center",cols="<,<,<,<,<",options="header"]
|===
2+| `vxrm[1:0]` | 缩写 | 舍入模式 | 舍入增量 `r`

| 0 | 0 | rnu | 四舍五入到最近向上（加 +0.5 LSB）          | `v[d-1]`
| 0 | 1 | rne | 四舍五入到最近偶数                       | `v[d-1] & (v[d-2:0]{ne}0 \| v[d])`
| 1 | 0 | rdn | 向下舍入                                  | `0`
| 1 | 1 | rod | 向奇数舍入（或位到 LSB，又称“jam”）  | `!v[d] & v[d-1:0]{ne}0`
|===

舍入函数：
----
roundoff_unsigned(v, d) = (unsigned(v) >> d) + r
roundoff_signed(v, d) = (signed(v) >> d) + r
----
用于表示以下指令描述中的此操作。

==== 向量定点饱和标志 (`vxsat`)

位 `vxsat[XLEN-1:1]` 应写入零。

`vxsat` 位镜像在 `vcsr` 中。

==== 复位时向量扩展的状态

向量扩展在复位时必须具有一致的状态。特别是，`vtype` 和 `vl` 必须具有可以通过单个 `vsetvl` 指令读取然后恢复的值。

NOTE: 建议在复位时，`vtype.vill` 设置，`vtype` 中其余位为零，`vl` 设置为零。

`vstart`、`vxrm`、`vxsat` CSR 在复位时可以具有任意值。

NOTE: 大多数向量单元的使用将需要初始的 `vset{i}vl{i}`，它将重置 `vstart`。`vxrm` 和 `vxsat` 字段在使用前应在软件中显式重置。

向量寄存器在复位时可以具有任意值。

[[sec-mask-register-layout]]
==== 掩码寄存器布局

无论 SEW 和 LMUL 如何，向量掩码只占用一个向量寄存器。

每个元素在掩码向量寄存器中分配一个掩码位。元素 _i_ 的掩码位位于掩码寄存器的位 _i_ 中，与 SEW 或 LMUL 无关。

=== 向量指令格式

向量扩展中的指令符合两个现有主要操作码（LOAD-FP 和 STORE-FP）和一个新主要操作码（OP-V）。

向量加载和存储编码在标量浮点加载和存储主要操作码（LOAD-FP/STORE-FP）中。向量加载和存储编码重新利用了标准标量浮点加载/存储 12 位立即数字段的一部分，以提供进一步的向量指令编码，其中位 25 包含标准向量掩码位（参见 <<sec-vector-mask-encoding>>）。

include::images/wavedrom/vmem-format.edn[]

include::images/wavedrom/valu-format.edn[]

include::images/wavedrom/vcfg-format.edn[]

向量指令可以具有标量或向量源操作数，并产生标量或向量结果，并且大多数向量指令可以无条件或有条件地在掩码下执行。

向量加载和存储在向量寄存器元素和内存之间移动位模式。向量算术指令对向量寄存器元素中保存的值进行操作。

==== 标量操作数

标量操作数可以是立即数，也可以取自 `x` 寄存器、`f` 寄存器或向量寄存器的元素 0。标量结果写入 `x` 或 `f` 寄存器或向量寄存器的元素 0。无论当前 LMUL 设置如何，任何向量寄存器都可以用于保存标量。

NOTE: Zfinx（“F in X”）是一个新的 ISA 扩展，其中浮点指令从整数寄存器文件获取参数。向量扩展也与 Zfinx 兼容，其中 Zfinx 向量扩展具有向量-标量浮点指令，其标量参数取自 `x` 寄存器。

NOTE: 我们考虑过但未追求将 `f` 寄存器叠加在 `v` 寄存器上。所采用的方法减少了向量寄存器压力，避免了与标准调用约定的交互，简化了高性能标量浮点设计，并提供了与 Zfinx ISA 选项的兼容性。将 `f` 与 `v` 叠加将提供降低某些实现中状态位数的好处，但会使高性能设计复杂化，并会阻止与 Zfinx ISA 选项的兼容性。

[[sec-vec-operands]]
==== 向量操作数

每个向量操作数都有一个 _有效_ _元素_ _宽度_ (EEW) 和一个 _有效_ LMUL (EMUL)，用于确定向量寄存器组中所有元素的大小和位置。默认情况下，对于大多数指令的大多数操作数，EEW=SEW 且 EMUL=LMUL。

一些向量指令具有相同元素数量但宽度不同的源和目标向量操作数，因此 EEW 和 EMUL 分别与 SEW 和 LMUL 不同，但 EEW/EMUL = SEW/LMUL。
例如，大多数加宽算术指令具有 EEW=SEW 且 EMUL=LMUL 的源组，但具有 EEW=2*SEW 且 EMUL=2*LMUL 的目标组。窄化指令具有 EEW=2*SEW 且 EMUL=2*LMUL 的源操作数，但目标 EEW=SEW 且 EMUL=LMUL。

向量操作数或结果可能占用一个或多个向量寄存器，具体取决于 EMUL，但始终使用组中编号最低的向量寄存器指定。使用除编号最低的向量寄存器之外的向量寄存器指定向量寄存器组是保留编码。

向量寄存器不能用于为单个指令提供具有多个 EEW 的源操作数。在此约束下，掩码寄存器源被视为 EEW=1。将导致同一向量寄存器以两个或更多不同 EEW 读取的编码是保留的，包括当向量寄存器出现在两个或更多向量寄存器组中的不同位置时。

NOTE: 实际上，在同一指令中以不同 EEW 读取同一寄存器没有软件好处，并且此约束降低了内部重新排列依赖于 EEW 的数据的实现的复杂性。

目标向量寄存器组只能与源向量寄存器组重叠，如果满足以下条件之一：

- 目标 EEW 等于源 EEW。
- 目标 EEW 小于源 EEW，并且重叠位于源寄存器组的最低编号部分（例如，当 LMUL=1 时，`vnsrl.wi v0, v0, 3` 是合法的，但目标为 `v1` 则不是）。
- 目标 EEW 大于源 EEW，源 EMUL 至少为 1，并且重叠位于目标寄存器组的最高编号部分（例如，当 LMUL=8 时，`vzext.vf4 v0, v6` 是合法的，但源为 `v0`、`v2` 或 `v4` 则不是）。

为了确定寄存器组重叠约束，掩码元素的 EEW=1。

NOTE: 重叠约束旨在支持没有寄存器重命名的机器中的可恢复异常。

任何违反重叠约束的指令编码都是保留的。

当源和目标寄存器重叠且具有不同的 EEW 时，无论 `vtype` 中 `vta` 和 `vma` 位的设置如何，指令都是掩码和尾部无关的。

指令使用的最大向量寄存器组不能大于 8 个向量寄存器（即 EMUL≤8），如果向量指令需要大于 8 个向量寄存器组，则指令编码是保留的。例如，当 LMUL=8 时，产生加宽向量寄存器组结果的加宽操作是保留的，因为这意味着结果 EMUL=16。

加宽的标量值，例如加宽归约操作的输入和输出，保存在向量寄存器的第一个元素中，并且 EMUL=1。

==== 向量掩码

许多向量指令都支持掩码。被屏蔽的元素操作（非活动）永远不会产生异常。与被屏蔽元素对应的目标向量寄存器元素根据 `vtype` 中 `vma` 位的设置（<<sec-agnostic>>）以掩码不受干扰或掩码无关策略处理。

用于控制被屏蔽向量指令执行的掩码值始终由向量寄存器 `v0` 提供。

NOTE: 掩码保存在向量寄存器中，而不是单独的掩码寄存器文件中，以减少总架构状态并简化 ISA。

NOTE: 未来的向量扩展可能会提供更长的指令编码，并为完整的掩码寄存器说明符留出空间。

被屏蔽向量指令的目标向量寄存器组不能与源掩码寄存器 (`v0`) 重叠，除非目标向量寄存器正在写入掩码值（例如，比较）或归约的标量结果。这些指令编码是保留的。

NOTE: 此约束支持以非零 `vstart` 值重新启动。

其他向量寄存器可用于保存工作掩码值，并提供掩码向量逻辑操作以执行谓词计算。[[sec-mask-vector-logical]]

如 <<sec-agnostic>> 中所述，无论 `vta` 的设置如何，掩码目标值始终被视为尾部无关。

| vm | 描述

| 0 | 向量结果，仅当 v0.mask[i] = 1 时
| 1 | 未屏蔽
|===

向量掩码在汇编代码中表示为另一个向量操作数，`.t` 表示操作在 `v0.mask[i]` 为 `1` 时发生（`t` 表示“真”）。如果未指定掩码操作数，则假定未屏蔽向量执行 (`vm=1`)。

----
    vop.v*    v1, v2, v3, v0.t  # v0.mask[i]=1 时启用，vm=0
    vop.v*    v1, v2, v3        # 未屏蔽向量操作，vm=1
----

NOTE: 尽管当前的向量扩展只支持一个向量掩码寄存器 `v0`，并且只支持谓词的真形式，但汇编语法将其完整写出，以与未来可能添加掩码寄存器说明符并支持真和补码掩码值的扩展兼容。掩码操作数上的 `.t` 后缀也有助于直观地编码掩码的使用。

NOTE: `.mask` 后缀不是汇编语法的一部分。
我们只在掩码向量被下标的上下文中附加它，例如 `v0.mask[i]`。

[[sec-inactive-defs]]
==== 预启动、活动、非活动、主体和尾部元素定义

向量指令执行期间操作的目标元素索引可以分为三个不相交的子集。

* _预启动_ 元素是指元素索引小于 `vstart` 寄存器中初始值的元素。预启动元素不引发异常，也不更新目标向量寄存器。

* _主体_ 元素是指元素索引大于或等于 `vstart` 寄存器中初始值且小于 `vl` 中当前向量长度设置的元素。主体可以分为两个不相交的子集：

** 向量指令执行期间的 _活动_ 元素是主体内的元素，并且当前掩码在该元素位置启用。活动元素可以引发异常并更新目标向量寄存器组。

** _非活动_ 元素是主体内的元素，但当前掩码在该元素位置禁用。非活动元素不引发异常，也不更新任何目标向量寄存器组，除非指定了掩码无关（`vtype.vma`=1），在这种情况下，非活动元素可能会被 1 覆盖。

* 向量指令执行期间的 _尾部_ 元素是超出 `vl` 中指定当前向量长度设置的元素。尾部元素不引发异常，也不更新任何目标向量寄存器组，除非指定了尾部无关（`vtype.vta`=1），在这种情况下，尾部元素可能会被 1 覆盖，或者在生成掩码的指令（掩码加载除外）的情况下，被指令的结果覆盖。当 LMUL < 1 时，尾部包括 VLMAX 之外的元素，这些元素保存在同一向量寄存器中。

----
    对于元素索引 x
    预启动(x) = (0 <= x < vstart)
    主体(x)     = (vstart <= x < vl)
    尾部(x)     = (vl <= x < max(VLMAX,VLEN/SEW))
    掩码(x)     = 未屏蔽 || v0.mask[x] == 1
    活动(x)   = 主体(x) && 掩码(x)
    非活动(x) = 主体(x) && !掩码(x)
----

当 `vstart` ≥ `vl` 时，没有主体元素，并且任何目标向量寄存器组中都没有元素更新，包括没有尾部元素用无关值更新。

NOTE: 因此，当 `vl`=0 时，无论 `vstart` 如何，目标向量寄存器组中都没有元素（包括无关元素）更新。

写入 `x` 寄存器或 `f` 寄存器的指令即使在 `vstart` ≥ `vl` 时也会执行，包括当 `vl`=0 时。

NOTE: 某些指令（例如 `vslidedown` 和 `vrgather`）可能会读取源向量寄存器组中超出 `vl` 甚至 VLMAX 的索引。一般策略是当源向量寄存器组中的索引大于 VLMAX 时返回 0。

[[sec-vector-config]]
=== 配置设置指令 (`vsetvli`/`vsetivli`/`vsetvl`)

处理大量元素的常见方法之一是“条带化”，其中循环的每次迭代处理一定数量的元素，并且迭代继续直到所有元素都已处理。RISC-V 向量规范为此方法提供了直接、可移植的支持。
应用程序指定要处理的元素总数（应用程序向量长度或 AVL）作为 `vl` 的候选值，硬件通过通用寄存器响应（通常较小）的每个迭代处理的元素数量（存储在 `vl` 中），基于微架构实现和 `vtype` 设置。<<example-stripmine-sew>> 中所示的简单循环结构描绘了代码跟踪剩余元素数量和硬件每迭代处理数量的简易性。

提供了一组指令，允许快速配置 `vl` 和 `vtype` 中的值以匹配应用程序需求。`vset{i}vl{i}` 指令根据其参数设置 `vtype` 和 `vl` CSR，并将 `vl` 的新值写入 `rd`。

----
 vsetvli rd, rs1, vtypei   # rd = 新 vl，rs1 = AVL，vtypei = 新 vtype 设置
 vsetivli rd, uimm, vtypei # rd = 新 vl，uimm = AVL，vtypei = 新 vtype 设置
 vsetvl  rd, rs1, rs2      # rd = 新 vl，rs1 = AVL，rs2 = 新 vtype 值
----

include::images/wavedrom/vcfg-format.edn[]

==== `vtype` 编码

include::images/wavedrom/vtype-format.edn[]

新的 `vtype` 值编码在 `vsetvli` 和 `vsetivli` 的立即数字段中，以及 `vsetvl` 的 `rs2` 寄存器中。

----
 vset{i}vli vtypei 立即数的建议汇编器名称

 e8    # SEW=8b
 e16   # SEW=16b
 e32   # SEW=32b
 e64   # SEW=64b

 mf8  # LMUL=1/8
 mf4  # LMUL=1/4
 mf2  # LMUL=1/2
 m1   # LMUL=1
 m2   # LMUL=2
 m4   # LMUL=4
 m8   # LMUL=8

示例：
    vsetvli t0, a0, e8, m1, ta, ma      # SEW= 8, LMUL=1
    vsetvli t0, a0, e8, m2, ta, ma      # SEW= 8, LMUL=2
    vsetvli t0, a0, e32, mf2, ta, ma    # SEW=32, LMUL=1/2
----

`vsetvl` 变体与 `vsetvli` 类似，只是它从 `rs2` 获取 `vtype` 值，并且可用于上下文恢复。

===== 不支持的 `vtype` 值

如果实现不支持 `vtype` 值，则 `vtype` 中的 `vill` 位设置，`vtype` 中其余位清零，`vl` 寄存器也清零。

NOTE: 早期草案要求在将 `vtype` 设置为非法值时捕获。然而，这将向 ISA 添加第一个依赖于数据的 CSR 写入捕获。实现可以选择在将非法值写入 `vtype` 时捕获，而不是设置 `vill`，以允许仿真支持新的配置以实现向前兼容性。当前方案支持通过检查给定设置的 `vill` 是否清除来轻量级运行时查询支持的向量单元配置。

设置了 `vill` 的 `vtype` 值被视为不支持的配置。

实现必须考虑 `vtype` 值的所有位以确定配置是否受支持。`vtype` 值中任何位置的不支持值都必须导致 `vill` 设置。

NOTE: 特别是，必须检查 `vsetvl` 指令的 `vtype` 参数的所有 XLEN 位。实现不能忽略它们未实现的字段。必须检查所有位，以确保假定不支持的向量功能的代码在旧实现上捕获而不是错误执行。

==== AVL 编码

新的向量长度设置基于 AVL，对于 `vsetvli` 和 `vsetvl`，它在 `rs1` 和 `rd` 字段中编码如下：

. `vsetvli` 和 `vsetvl` 指令中使用的 AVL
[cols="2,2,10,10"]
[%autowidth,float="center",align="center",options="header"]
|===
|  `rd`  | `rs1`  | AVL 值         | 对 `vl` 的影响
|  -     | !x0    | `x[rs1]` 中的值 | 正常条带化
| !x0    |  x0    | ~0                | 将 `vl` 设置为 VLMAX
|  x0    |  x0    | `vl` 寄存器中的值 | 保持现有 `vl`（当然，`vtype` 可能会改变）
|===

当 _rs1_ 不是 `x0` 时，AVL 是一个保存在 _rs1_ 指定的 `x` 寄存器中的无符号整数，并且新的 `vl` 值也写入 _rd_ 指定的 `x` 寄存器。

当 _rs1_=`x0` 但 _rd_≠`x0` 时，最大无符号整数值 (`~0`) 用作 AVL，并且生成的 VLMAX 写入 `vl` 并写入 `rd` 指定的 `x` 寄存器。

当 _rs1_=`x0` 且 _rd_=`x0` 时，指令的行为就像当前 `vl` 中的向量长度用作 AVL，并且结果值写入 `vl`，但不写入目标寄存器。此形式只能在 VLMAX 且因此 `vl` 不因新的 SEW/LMUL 比率而实际改变时使用。使用具有新的 SEW/LMUL 比率的指令将导致 VLMAX 改变的情况是保留的。
如果 `vill` 之前为 1，则指令的使用也是保留的。
在任何一种情况下，实现都可以设置 `vill`。

NOTE: 指令的最后一种形式允许更改 `vtype` 寄存器，同时保持当前 `vl`，前提是 VLMAX 不减小。此设计旨在确保 `vl` 始终为当前 `vtype` 设置保存合法值。当前的 `vl` 值可以从 `vl` CSR 读取。如果新的 SEW/LMUL 比率导致 VLMAX 缩小，则这些指令可能会减小 `vl` 值，因此这种情况已被保留，因为它不清楚这是否是普遍有用的操作，并且实现可以假定这些指令不会更改 `vl` 以优化其微架构。

对于 `vsetivli` 指令，AVL 编码为 `rs1` 字段中的 5 位零扩展立即数 (0-31)。

NOTE: `vsetivli` 的 AVL 编码与常规 CSR 立即数相同。

NOTE: 当向量维度较小且已知适合向量寄存器时，`vsetivli` 指令提供了更紧凑的代码，在这种情况下没有条带化开销。

[[constraints-on-setting-vl]]
==== 设置 `vl` 的约束

`vset{i}vl{i}` 指令首先根据其 `vtype` 参数设置 VLMAX，然后遵循以下约束设置 `vl`：

. 如果 `AVL ≤ VLMAX`，则 `vl = AVL`
. 如果 `AVL < (2 * VLMAX)`，则 `ceil(AVL / 2) ≤ vl ≤ VLMAX`
. 如果 `AVL ≥ (2 * VLMAX)`，则 `vl = VLMAX`
. 对于相同的输入 AVL 和 VLMAX 值，在任何给定实现上都是确定性的
. 这些特定属性遵循先前的规则：
.. 如果 `AVL = 0`，则 `vl = 0`
.. 如果 `AVL > 0`，则 `vl > 0`
.. `vl ≤ VLMAX`
.. `vl ≤ AVL`
.. 从 `vl` 读取的值用作 `vset{i}vl{i}` 的 AVL 参数时，会产生相同的 `vl` 值，前提是结果 VLMAX 等于读取 `vl` 时的 VLMAX 值

[NOTE]
--
`vl` 设置规则旨在足够严格，以在寄存器溢出和上下文交换时保留 `vl` 行为（对于 `AVL ≤ VLMAX`），但又足够灵活，以使实现能够提高 `AVL > VLMAX` 的向量通道利用率。

例如，这允许实现将 `vl = ceil(AVL / 2)` 设置为 `VLMAX < AVL < 2*VLMAX`，以便在条带化循环的最后两次迭代中均匀分配工作。
要求 2 确保归约循环的第一次条带化迭代使用所有迭代中最大的向量长度，即使在 `AVL < 2*VLMAX` 的情况下也是如此。
这允许软件避免需要显式计算条带化循环期间观察到的向量长度的运行最大值。
要求 2 还允许实现将 vl 设置为 VLMAX，对于 `VLMAX < AVL < 2*VLMAX`。
--

[[example-stripmine-sew]]
==== 条带化和 SEW 更改示例

SEW 和 LMUL 设置可以动态更改，以在单个循环中提供混合宽度操作的高吞吐量。
----
# 示例：加载 16 位值，加宽乘法到 32b，将 32b 结果右移 3 位，存储 32b 值。
# 入口处：
#  a0 保存要处理的元素总数
#  a1 保存源数组的地址
#  a2 保存目标数组的地址

loop:
    vsetvli a3, a0, e16, m4, ta, ma  # vtype = 16 位整数向量；
                                     # 同时用 vl（本次迭代的元素数）更新 a3
    vle16.v v4, (a1)        # 获取 16b 向量
    slli t1, a3, 1          # 将本次迭代的元素数乘以 2 字节/源元素
    add a1, a1, t1          # 增加指针
    vwmul.vx v8, v4, x10    # 加宽乘法到 32b，结果在 <v8--v15> 中

    vsetvli x0, x0, e32, m8, ta, ma  # 操作 32b 值
    vsrl.vi v8, v8, 3
    vse32.v v8, (a2)        # 存储 32b 元素的向量
    slli t1, a3, 2          # 将本次迭代的元素数乘以 4 字节/目标元素
    add a2, a2, t1          # 增加指针
    sub a0, a0, a3          # 递减计数
    bnez a0, loop           # 还有吗？
----

[[sec-vector-memory]]
=== 向量加载和存储

向量加载和存储在向量寄存器和内存之间移动值。
向量加载和存储可以被屏蔽，并且它们只访问内存或为活动元素引发异常。
被屏蔽的向量加载不更新目标向量寄存器组中的非活动元素，除非指定了掩码无关（`vtype.vma`=1）。
所有向量加载和存储都可以生成并接受非零 `vstart` 值。

==== 向量加载/存储指令编码

向量加载和存储编码在标量浮点加载和存储主要操作码（LOAD-FP/STORE-FP）中。向量加载和存储编码重新利用了标准标量浮点加载/存储 12 位立即数字段的一部分，以提供进一步的向量指令编码，其中位 25 包含标准向量掩码位（参见 <<sec-vector-mask-encoding>>）。

include::images/wavedrom/vmem-format.edn[]

[cols="4,12"]
|===
| 字段      | 描述

| rs1[4:0]   | 指定保存基地址的 x 寄存器
| rs2[4:0]   | 指定保存步长的 x 寄存器
| vs2[4:0]   | 指定保存地址偏移量的 v 寄存器
| vs3[4:0]   | 指定保存存储数据的 v 寄存器
| vd[4:0]    | 指定加载的目标 v 寄存器
| vm         | 指定是否启用向量掩码（0 = 掩码启用，1 = 掩码禁用）
| width[2:0] | 指定内存元素的大小，并与 FP 标量区分
| mew        | 扩展内存元素宽度。参见 <<sec-vector-loadstore-width-encoding>>
| mop[1:0]   | 指定内存寻址模式
| nf[2:0]    | 指定每个段中的字段数量，用于段加载/存储
| lumop[4:0]/sumop[4:0] | 是编码单位步长指令变体的附加字段
|===

向量内存单位步长和常量步长操作直接在指令中静态编码要传输数据的 EEW，以减少在混合宽度例程中访问内存时 `vtype` 更改的数量。索引操作使用指令中显式 EEW 编码来设置使用的索引大小，并使用 SEW/LMUL 来指定数据宽度。

==== 向量加载/存储寻址模式

向量扩展支持单位步长、常量步长和索引（分散/聚集）寻址模式。向量加载/存储基址寄存器和步长取自 GPR `x` 寄存器。

所有向量访问的基有效地址由 `rs1` 中命名的 `x` 寄存器内容给出。

向量单位步长操作从基有效地址开始访问内存中连续存储的元素。

向量常量步长操作访问基有效地址处的第一个内存元素，然后以 `rs2` 指定的 `x` 寄存器中包含的字节偏移量递增的地址访问后续元素。

向量索引操作将 `vs2` 指定的向量偏移操作数中每个元素的内容添加到基有效地址，以给出每个元素的有效地址。数据向量寄存器组的 EEW=SEW，EMUL=LMUL，而偏移向量寄存器组的 EEW 在指令中编码，EMUL=(EEW/SEW)*LMUL。

向量偏移操作数被视为字节地址偏移量的向量。

NOTE: 索引操作也可以用于访问对象向量中的字段，其中 `vs2` 向量保存指向对象基址的指针，标量 `x` 寄存器保存每个对象中成员字段的偏移量。支持这种情况是索引操作未定义为按数据 EEW 缩放元素索引的原因。

如果向量偏移元素窄于 XLEN，则在添加到基有效地址之前，它们会零扩展到 XLEN。如果向量偏移元素宽于 XLEN，则在地址计算中使用最低有效 XLEN 位。如果 EEW 不支持偏移元素，则实现必须引发非法指令异常。

NOTE: 配置文件可以对最大支持索引 EEW（例如，仅到 XLEN）施加上限，该上限小于 ELEN。

向量寻址模式使用 2 位 `mop[1:0]` 字段编码。

.加载编码
[cols="1,1,7,6"]
|===
2+| mop [1:0] | 描述 | 操作码

| 0 | 0 | 单位步长       | VLE<EEW>
| 0 | 1 | 索引-无序 | VLUXEI<EEW>
| 1 | 0 | 常量步长   | VLSE<EEW>
| 1 | 1 | 索引-有序   | VLOXEI<EEW>
|===

.存储编码
[cols="1,1,7,6"]
|===
2+| mop [1:0] | 描述 | 操作码

| 0 | 0 | 单位步长       | VSE<EEW>
| 0 | 1 | 索引-无序 | VSUXEI<EEW>
| 1 | 0 | 常量步长   | VSSE<EEW>
| 1 | 1 | 索引-有序   | VSOXEI<EEW>
|===

向量单位步长和常量步长内存访问不保证单个元素访问之间的排序。向量索引加载和存储内存操作有两种形式：有序和无序。索引-有序变体在内存访问上保留元素排序。

对于无序指令（`mop[1:0]`!=11），不保证元素访问顺序。如果访问的是强序 IO 区域，则元素访问可以以任何顺序启动。

NOTE: 为了向强序 IO 区域提供有序向量访问，应使用有序索引指令。

对于具有精确向量陷阱的实现，索引-无序存储上的异常也必须精确。

附加单位步长向量寻址模式分别使用单位步长加载和存储指令编码中的 5 位 `lumop` 和 `sumop` 字段编码。

.lumop
[cols="1,1,1,1,1,11"]
|===
5+| lumop[4:0] | 描述

| 0 | 0 | 0 | 0 | 0 | 单位步长加载
| 0 | 1 | 0 | 0 | 0 | 单位步长，全寄存器加载
| 0 | 1 | 0 | 1 | 1 | 单位步长，掩码加载，EEW=8
| 1 | 0 | 0 | 0 | 0 | 单位步长仅故障优先
| x | x | x | x | x | 其他编码保留
|===

.sumop
[cols="1,1,1,1,1,11"]
|===
5+| sumop[4:0] | 描述

| 0 | 0 | 0 | 0 | 0 | 单位步长存储
| 0 | 1 | 0 | 0 | 0 | 单位步长，全寄存器存储
| 0 | 1 | 0 | 1 | 1 | 单位步长，掩码存储，EEW=8
| x | x | x | x | x | 其他编码保留
|===

`nf[2:0]` 字段编码每个段中的字段数量。对于常规向量加载和存储，`nf`=0，表示在每个元素位置，单个值在向量寄存器组和内存之间移动。`nf` 字段中较大的值用于访问段内的多个连续字段，如 <<sec-aos>> 中所述。

`nf[2:0]` 字段还编码全向量寄存器加载/存储指令要传输的整个向量寄存器数量。

[[sec-vector-loadstore-width-encoding]]
==== 向量加载/存储宽度编码

向量加载和存储在指令中直接编码 EEW。相应的 EMUL 计算为 EMUL = (EEW/SEW)*LMUL。如果 EMUL 超出范围（EMUL>8 或 EMUL<1/8），则指令编码是保留的。向量寄存器组必须具有所选 EMUL 的合法寄存器说明符，否则指令编码是保留的。

向量单位步长和常量步长使用指令中编码的 EEW/EMUL 作为数据值，而向量索引加载和存储使用指令中编码的 EEW/EMUL 作为索引值，并使用 `vtype` 中编码的 SEW/LMUL 作为数据值。

向量加载和存储使用未被标准标量浮点加载和存储占用的宽度值进行编码。

实现必须提供 EEW 对应于所有支持的 SEW 设置的向量加载和存储。不支持 EEW 宽度的向量加载/存储编码必须引发非法指令异常。

.向量加载和存储的宽度编码。
[cols="5,1,1,1,1,>3,>3,>3,3"]
|===
|                  | mew 3+| width [2:0] | 内存位 | 数据寄存器位 | 索引位 | 操作码

| 标准标量 FP   | x |   0 | 0 | 1 |   16| FLEN | -  | FLH/FSH
| 标准标量 FP   | x |   0 | 1 | 0 |   32| FLEN | -  | FLW/FSW
| 标准标量 FP   | x |   0 | 1 | 1 |   64| FLEN | -  | FLD/FSD
| 标准标量 FP   | x |   1 | 0 | 0 |  128| FLEN | -  | FLQ/FSQ
| 向量 8b 元素    | 0 |   0 | 0 | 0 |    8|    8 | -  | VLxE8/VSxE8
| 向量 16b 元素   | 0 |   1 | 0 | 1 |   16|   16 | -  | VLxE16/VSxE16
| 向量 32b 元素   | 0 |   1 | 1 | 0 |   32|   32 | -  | VLxE32/VSxE32
| 向量 64b 元素   | 0 |   1 | 1 | 1 |   64|   64 | -  | VLxE64/VSxE64
| 向量 8b 索引      | 0 |   0 | 0 | 0 | SEW | SEW  |  8 | VLxEI8/VSxEI8
| 向量 16b 索引     | 0 |   1 | 0 | 1 | SEW | SEW  | 16 | VLxEI16/VSxEI16
| 向量 32b 索引     | 0 |   1 | 1 | 0 | SEW | SEW  | 32 | VLxEI32/VSxEI32
| 向量 64b 索引     | 0 |   1 | 1 | 1 | SEW | SEW  | 64 | VLxEI64/VSxEI64

内存位是内存中每个元素的大小。

数据寄存器位是寄存器中每个数据元素的大小。

索引位是寄存器中每个索引的大小。

`mew` 位 (`inst[28]`) 设置时，预计将用于编码 128 位及以上的扩展内存大小，但这些编码目前是保留的。

==== 向量单位步长指令

----
# 向量单位步长加载和存储

# vd 目标，rs1 基地址，vm 是掩码编码（v0.t 或 <缺失>）
vle8.v    vd, (rs1), vm  #    8 位单位步长加载
vle16.v   vd, (rs1), vm  #   16 位单位步长加载
vle32.v   vd, (rs1), vm  #   32 位单位步长加载
vle64.v   vd, (rs1), vm  #   64 位单位步长加载

# vs3 存储数据，rs1 基地址，vm 是掩码编码（v0.t 或 <缺失>）
vse8.v    vs3, (rs1), vm  #    8 位单位步长存储
vse16.v   vs3, (rs1), vm  #   16 位单位步长存储
vse32.v   vs3, (rs1), vm  #   32 位单位步长存储
vse64.v   vs3, (rs1), vm  #   64 位单位步长存储
----

提供了额外的单位步长掩码加载和存储指令，用于在内存之间传输掩码值。这些指令的操作类似于未屏蔽的字节加载或存储 (EEW=8)，不同之处在于有效向量长度为 ``evl``=ceil(``vl``/8)（即 EMUL=1），并且目标寄存器始终以尾部无关策略写入。

----
# 向量单位步长掩码加载
vlm.v vd, (rs1)   #  加载长度为 ceil(vl/8) 的字节向量

# 向量单位步长掩码存储
vsm.v vs3, (rs1)  #  存储长度为 ceil(vl/8) 的字节向量
----

`vlm.v` 和 `vsm.v` 使用与 `vle8.v` 和 `vse8.v` 相同的 `width[2:0]`=0 编码，但通过不同的 `lumop` 和 `sumop` 编码进行区分。由于 `vlm.v` 和 `vsm.v` 作为字节加载和存储操作，因此 `vstart` 对于这些指令以字节为单位。

NOTE: `vlm.v` 和 `vsm.v` 尊重 `vtype` 中的 `vill` 字段，因为它们通过 `vtype` 对 `vl` 的约束间接依赖于 `vtype`。

NOTE: 以前的汇编器助记符 `vle1.v` 和 `vse1.v` 令人困惑，因为这些指令的长度处理方式与元素加载/存储指令不同。为了避免软件混乱，这些旧的汇编助记符仍保留为别名。

NOTE: 提供掩码加载和存储的主要动机是支持内部重新排列数据以减少交叉数据路径布线的机器。然而，这些指令也提供了一种方便的机制，可以将内存中的打包位向量用作掩码值，并通过减少更改 `vl` 的需要来降低掩码溢出/填充的成本。

==== 向量常量步长指令

----
# 向量常量步长加载和存储

# vd 目标，rs1 基地址，rs2 字节常量步长
vlse8.v    vd, (rs1), rs2, vm  #    8 位常量步长加载
vlse16.v   vd, (rs1), rs2, vm  #   16 位常量步长加载
vlse32.v   vd, (rs1), rs2, vm  #   32 位常量步长加载
vlse64.v   vd, (rs1), rs2, vm  #   64 位常量步长加载

# vs3 存储数据，rs1 基地址，rs2 字节常量步长
vsse8.v    vs3, (rs1), rs2, vm  #    8 位常量步长存储
vsse16.v   vs3, (rs1), rs2, vm  #   16 位常量步长存储
vsse32.v   vs3, (rs1), rs2, vm  #   32 位常量步长存储
vsse64.v   vs3, (rs1), rs2, vm  #   64 位常量步长存储
----

支持负步长和零步长。

常量步长指令中的元素访问彼此之间是无序的。

当 `rs2`=`x0` 时，允许（但不要求）实现执行少于活动元素数量的内存操作，并且可以在同一静态指令的不同动态执行中执行不同数量的内存操作。

NOTE: 编译器必须注意，如果意图是要求执行所有内存访问，则当立即步长为 `0` 时，不要将 `x0` 形式用于 rs2。

当 `rs2!=x0` 且 `x[rs2]=0` 时，实现必须为每个活动元素执行一次内存访问（但这些访问将是无序的）。

NOTE: 与其他架构规定一样，实现必须 _看起来_ 执行每个内存访问。微架构可以自由地优化掉其他代理不会观察到的访问，例如，在遵守 RVWMO 的幂等内存区域中。对于非幂等内存区域，根据定义，每个访问都可以被设备观察到，因此无法进行优化。

NOTE: 当需要对同一内存地址重复有序向量访问时，可以使用有序索引操作。

==== 向量索引指令

----
# 向量索引加载和存储

# 向量索引-无序加载指令
# vd 目标，rs1 基地址，vs2 字节偏移量
vluxei8.v    vd, (rs1), vs2, vm  # 无序 8 位索引加载 SEW 数据
vluxei16.v   vd, (rs1), vs2, vm  # 无序 16 位索引加载 SEW 数据
vluxei32.v   vd, (rs1), vs2, vm  # 无序 32 位索引加载 SEW 数据
vluxei64.v   vd, (rs1), vs2, vm  # 无序 64 位索引加载 SEW 数据

# 向量索引-有序加载指令
# vd 目标，rs1 基地址，vs2 字节偏移量
vloxei8.v    vd, (rs1), vs2, vm  # 有序 8 位索引加载 SEW 数据
vloxei16.v   vd, (rs1), vs2, vm  # 有序 16 位索引加载 SEW 数据
vloxei32.v   vd, (rs1), vs2, vm  # 有序 32 位索引加载 SEW 数据
vloxei64.v   vd, (rs1), vs2, vm  # 有序 64 位索引加载 SEW 数据

# 向量索引-无序存储指令
# vs3 存储数据，rs1 基地址，vs2 字节偏移量
vsuxei8.v   vs3, (rs1), vs2, vm # 无序 8 位索引存储 SEW 数据
vsuxei16.v  vs3, (rs1), vs2, vm # 无序 16 位索引存储 SEW 数据
vsuxei32.v  vs3, (rs1), vs2, vm # 无序 32 位索引存储 SEW 数据
vsuxei64.v  vs3, (rs1), vs2, vm # 无序 64 位索引存储 SEW 数据

# 向量索引-有序存储指令
# vs3 存储数据，rs1 基地址，vs2 字节偏移量
vsoxei8.v    vs3, (rs1), vs2, vm  # 有序 8 位索引存储 SEW 数据
vsoxei16.v   vs3, (rs1), vs2, vm  # 有序 16 位索引存储 SEW 数据
vsoxei32.v   vs3, (rs1), vs2, vm  # 有序 32 位索引存储 SEW 数据
vsoxei64.v   vs3, (rs1), vs2, vm  # 有序 64 位索引存储 SEW 数据
----

NOTE: 索引加载和存储的汇编语法使用 ``ei``__x__ 而不是 ``e``__x__ 来指示静态编码的 EEW 是索引而不是数据。

NOTE: 索引操作助记符带有“U”或“O”以区分无序和有序，而其他向量寻址模式没有字符。虽然这可能不太一致，但这种方法最大限度地减少了对现有软件的干扰，因为 VSXEI 以前表示“有序”——并且操作码可以在转换期间保留为别名，以帮助减少软件混乱。

==== 单位步长仅故障优先加载

单位步长仅故障优先加载指令用于向量化具有数据相关退出条件（“while”循环）的循环。这些指令作为常规加载执行，只是它们只会在元素 0 上发生同步异常时捕获。如果元素 0 引发异常，`vl` 不会修改，并且捕获发生。如果元素 > 0 引发异常，则不发生相应的捕获，并且向量长度 `vl` 减小到将引发异常的元素的索引。

加载指令可能会覆盖活动目标向量寄存器组中超出报告陷阱的元素索引的元素。同样，仅故障优先加载指令可能会更新活动目标元素，超出导致向量长度截断的元素（但不会超出原始向量长度）。这些虚假更新的值不必与寻址内存位置处的内存中的值对应。非幂等内存位置只能在已知相应元素加载操作不会因陷阱或向量长度截断而重新启动时才能访问。

----
# 向量单位步长仅故障优先加载

# vd 目标，rs1 基地址，vm 是掩码编码（v0.t 或 <缺失>）
vle8ff.v    vd, (rs1), vm  #    8 位单位步长仅故障优先加载
vle16ff.v   vd, (rs1), vm  #   16 位单位步长仅故障优先加载
vle32ff.v   vd, (rs1), vm  #   32 位单位步长仅故障优先加载
vle64ff.v   vd, (rs1), vm  #   64 位单位步长仅故障优先加载
----

----
使用单位步长仅故障优先指令的 strlen 示例

include::example/strlen.s[lines=4..-1]
----

NOTE: 仅故障优先加载存在安全隐患，因为它们可用于探测有效地址。单位步长版本只允许探测紧邻已知区域的区域，因此在非特权代码中使用时可降低安全影响。然而，在 S 模式下运行的代码可以建立任意页面转换，从而允许探测 hypervisor 提供的随机客户机物理地址。由于编码空间不足，未提供常量步长和分散/聚集仅故障优先指令，但它们也可能代表更大的安全漏洞，允许甚至非特权软件轻松检查多个随机页面的可访问性而不会发生陷阱。本标准不解决仅故障优先指令可能的安全缓解措施。

即使未引发异常，实现也允许处理少于 `vl` 个元素并相应地减小 `vl`，但如果 `vstart`=0 且 `vl`>0，则必须至少处理一个元素。

当仅故障优先指令因中断而发生陷阱时，实现不应减小 `vl`，而应设置 `vstart` 值。

NOTE: 当仅故障优先指令在第一个元素之后触发调试数据监视点陷阱时，实现不应减小 `vl`，而应触发调试陷阱，否则事件可能会丢失。

==== 向量加载/存储段指令

向量加载/存储段指令将内存中的多个连续字段移动到连续编号的向量寄存器中。

NOTE: 名称“段”反映了移动的项是具有同质元素的子数组。这些操作可用于在内存和寄存器之间转置数组，并可支持对“结构数组”数据类型进行操作，方法是将结构中的每个字段解包到单独的向量寄存器中。

向量指令编码中的三位 `nf` 字段是一个无符号整数，它包含每个段的字段数量减一，_NFIELDS_。

[[fig-nf]]
.NFIELDS 编码
[cols="1,1,1,13"]
|===
3+| nf[2:0] | NFIELDS

| 0 | 0 | 0 | 1
| 0 | 0 | 1 | 2
| 0 | 1 | 0 | 3
| 0 | 1 | 1 | 4
| 1 | 0 | 0 | 5
| 1 | 0 | 1 | 6
| 1 | 1 | 0 | 7
| 1 | 1 | 1 | 8
|===

EMUL 设置必须使得 EMUL * NFIELDS ≤ 8，否则指令编码是保留的。

NOTE: 乘积 ceil(EMUL) * NFIELDS 表示分段加载或存储指令将触及的底层向量寄存器数量。此约束使得此总数不超过架构寄存器文件的 1/4，并且与 EMUL=8 的常规操作相同。

每个字段将保存在连续编号的向量寄存器组中。当 EMUL>1 时，每个字段将占用一个保存在多个连续编号向量寄存器中的向量寄存器组，并且每个字段的向量寄存器组必须遵循常规向量寄存器对齐约束（例如，当 EMUL=2 且 NFIELDS=4 时，每个字段的向量寄存器组必须从偶数向量寄存器开始，但不必从 8 的倍数向量寄存器编号开始）。

如果分段加载或存储访问的向量寄存器编号将递增超过 31，则指令编码是保留的。

NOTE: 此约束旨在帮助实现与未来可能更长的指令编码的向前兼容性，该编码具有更多可寻址的向量寄存器。

`vl` 寄存器给出要移动的段数，这等于传输到每个向量寄存器组的元素数量。掩码也应用于整个段级别。

对于段加载和存储，用于访问每个段内字段的单个内存访问彼此之间是无序的，即使对于有序索引段加载和存储也是如此。

`vstart` 值以整个段为单位。如果在访问段期间发生陷阱，则在捕获陷阱之前是否执行故障段的子集是实现定义的。

===== 向量单位步长段加载和存储

向量单位步长加载和存储段指令将打包的连续段移动到多个目标向量寄存器组中。

NOTE: 当段包含具有异构大小字段的结构时，软件可以在段加载将数据带入向量寄存器后，使用附加指令解包单个结构字段。

汇编器前缀 `vlseg`/`vsseg` 分别用于单位步长段加载和存储。

----
# 格式
# 在此语法中，<nf> 等于 NFIELDS，是一个范围在 [2, 8] 的整数。
vlseg<nf>e<eew>.v vd, (rs1), vm      # 单位步长段加载模板
vsseg<nf>e<eew>.v vs3, (rs1), vm     # 单位步长段存储模板

# 示例
vlseg8e8.v vd, (rs1), vm   # 加载八个向量寄存器，每个寄存器包含八个字节字段。

vsseg3e32.v vs3, (rs1), vm  # 存储来自 vs3,vs3+1,vs3+2 的 3*4 字节段的打包向量到内存
----

对于加载，`vd` 寄存器将保存从段中加载的第一个字段。对于存储，读取 `vs3` 寄存器以提供要存储到每个段的第一个字段。

----
# 示例 1
# 内存结构保存打包的 RGB 像素（24 位数据结构，8bpp）
vsetvli a1, t0, e8, m1, ta, ma
vlseg3e8.v v8, (a0), vm
# v8 保存红色像素
# v9 保存绿色像素
# v10 保存蓝色像素

# 示例 2
# 内存结构保存复数值，实部 32b，虚部 32b
vsetvli a1, t0, e32, m1, ta, ma
vlseg2e32.v v8, (a0), vm
# v8 保存实部
# v9 保存虚部
----

还有单位步长指令的仅故障优先版本。

----
# 向量仅故障优先单位步长段加载模板。
vlseg<nf>e<eew>ff.v vd, (rs1),  vm    # 单位步长仅故障优先段加载
----

对于仅故障优先段加载，如果在访问零号段时检测到异常，则捕获发生。
如果在访问后续段时检测到异常，则 `vl` 减小到该段的索引。
在这两种情况下，是否加载段的子集是实现定义的。

这些指令可能会覆盖目标向量寄存器组中超出报告陷阱点或超出向量长度截断点的元素。

===== 向量常量步长段加载和存储

向量常量步长段加载和存储移动连续段，其中每个段位于通过将 `rs1` 字段中的标量基地址添加到向量寄存器 `vs2` 中的字节偏移量来给出的地址处。

NOTE: 支持负步长和零步长。

----
# 格式
vlsseg<nf>e<eew>.v vd, (rs1), rs2, vm          # 常量步长段加载
vssseg<nf>e<eew>.v vs3, (rs1), rs2, vm         # 常量步长段存储

# 示例
vsetvli a1, t0, e8, m1, ta, ma
vlsseg3e8.v v4, (x5), x6   # 将地址 x5+i*x6 处的字节加载到 v4[i] 中，
                            #  并将地址 x5+i*x6+1 处的字节加载到 v5[i] 中，
                            #  并将地址 x5+i*x6+2 处的字节加载到 v6[i] 中。

# 示例
vsetvli a1, t0, e32, m1, ta, ma
vssseg2e32.v v2, (x5), x6   # 将 v2[i] 中的字存储到地址 x5+i*x6
                                #   并将 v3[i] 中的字存储到地址 x5+i*x6+4
----

每个段内字段的访问可以以任何顺序发生，包括字节步长导致段在内存中重叠的情况。

===== 向量索引段加载和存储

向量索引段加载和存储移动连续段，其中每个段位于通过将 `rs1` 字段中的标量基地址添加到向量寄存器 `vs2` 中的字节偏移量来给出的地址处。
提供了有序和无序两种形式，其中有序形式按元素顺序访问段。然而，即使对于有序形式，单个段内字段的访问彼此之间也是无序的。

数据向量寄存器组的 EEW=SEW，EMUL=LMUL，而索引向量寄存器组的 EEW 在指令中编码，EMUL=(EEW/SEW)*LMUL。
EMUL * NFIELDS ≤ 8 约束适用于数据向量寄存器组。

----
# 格式
vluxseg<nf>ei<eew>.v vd, (rs1), vs2, vm   # 索引-无序段加载
vloxseg<nf>ei<eew>.v vd, (rs1), vs2, vm   # 索引-有序段加载
vsuxseg<nf>ei<eew>.v vs3, (rs1), vs2, vm  # 索引-无序段存储
vsoxseg<nf>ei<eew>.v vs3, (rs1), vs2, vm  # 索引-有序段存储

# 示例
vsetvli a1, t0, e8, m1, ta, ma
vluxseg3ei8.v v4, (x5), v3   # 将地址 x5+v3[i] 处的字节加载到 v4[i] 中，
                                #  并将地址 x5+v3[i]+1 处的字节加载到 v5[i] 中，
                                #  并将地址 x5+v3[i]+2 处的字节加载到 v6[i] 中。

# 示例
vsetvli a1, t0, e32, m1, ta, ma
vsuxseg2ei32.v v2, (x5), v5   # 将 v2[i] 中的字存储到地址 x5+v5[i]
                                #   并将 v3[i] 中的字存储到地址 x5+v5[i]+4
----

对于向量索引段加载，目标向量寄存器组不能与源向量寄存器组（由 `vs2` 指定）重叠，否则指令编码是保留的。

NOTE: 此约束支持在加载结构时引发异常的索引段加载的重新启动。
