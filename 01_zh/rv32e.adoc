== RV32E 和 RV64E 基本整数指令集，版本 2.0
本章描述了 RV32E 和 RV64E 基本整数指令集的提案，该提案专为嵌入式系统中的微控制器设计。RV32E 和 RV64E 分别是 RV32I 和 RV64I 的精简版本：唯一的更改是将整数寄存器数量减少到 16 个。本章仅概述了 RV32E/RV64E 和 RV32I/RV64I 之间的差异，因此应在阅读 <<rv32>> 和 <<rv64>> 之后阅读。
(((RV32E，设计)))
[NOTE]
====
RV32E 旨在为嵌入式微控制器提供更小的基本核心。在大型 SoC 设计中，RV64E 也引起了人们的兴趣，并且可以减少高线程 64 位处理器的上下文状态。

除非另有说明，否则与 RV32I 和 RV64I 兼容的标准扩展也分别与 RV32E 和 RV64E 兼容。
====

=== RV32E 和 RV64E 程序员模型
RV32E 和 RV64E 将整数寄存器数量减少到 16 个通用寄存器（`x0-x15`），其中 `x0` 是专用零寄存器。

[NOTE]
====
我们发现在小型 RV32I 核心实现中，高 16 个寄存器消耗了核心（不包括内存）总面积的约四分之一，因此它们的移除节省了约 25% 的核心面积，并相应地降低了核心功耗。
====

=== RV32E 和 RV64E 指令集编码
(((RV32E，与 RV32I 的区别)))
RV32E 和 RV64E 使用与 RV32I 和 RV64I 相同的指令集编码，只是仅提供寄存器 `x0-x15`。所有指定其他寄存器 `x16-x31` 的编码都保留。

[NOTE]
====
本章的先前草案将所有使用 `x16-x31` 寄存器的编码都作为自定义可用。此版本采用更保守的方法，将这些编码保留，以便将来可以在自定义空间或新标准编码之间分配。
====
